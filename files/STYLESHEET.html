The design of the clock in one page: monochrome, one character grid, bold and dim. Read from the code, offline, reusable. One style, four media: the terminal, the resume, the CV and the presentation, each in its own fold below.

The folds below only say what changes for that medium. A fold is a heading with › (closed) or ↓ (open); the keys are e expand all and c collapse all, and print or PDF always opens everything.

Terminal and web view terminalclock: the original rules

Rules

  • Monochrome. White text, bold and dim only. No cyan, red, green or yellow. No new glyph decoration.
  • No filled buttons. A clickable shortcut is plain text with its key in brackets: History (h). The mouse only sends the key the keyboard has. Every action has a key.
  • Same format as the neighbours. About lines are table rows (dim right-aligned label, value); hints are one dim line in the footer; lists mark the selection with ›. Look at a similar panel first.
  • Layout. Content is centred as one block; shortcut buttons sit at the bottom just above the subtitle. A tab returns at most body_lines - 2 lines: every mode keeps the same frame height. Show all items, not only the selected one.
  • Long text. Never run past the frame: clip with …, and make the limit a setting.
  • Text boxes. While a box is open every key is text; esc leaves it, then q quits.
  • State wording. Say what is true now: Currently: Offline, with a way to the setting that changes it.

Type and grid

  • One monospace grid. The terminal draws it in whatever font the user chose; the docs and the web view use ui-monospace, Menlo, Consolas, monospace (screenshots: Fira Code, then the system monospace).
  • Size and rhythm. Web view default: 13px/1.15, auto-fit to the screen (6–120 px). Layout is in character cells, never pixels.
  • UI chrome outside the grid (the web view's buttons and help): system-ui, sans-serif, 14px.
  • Widths. Check every panel at 70 and 100 columns. Device default grid: 80 × 30. Frame: padding 1 line, 4 columns.
  • Icons. None. Only the glyphs listed below. Nerd Font icons are used by yazi, not by the clock's own panels.

JavaScript: big digits 
// Big block digits exactly as the clock draws them: every cell doubled, two spaces between glyphs.
function tcBigText(s, blinkOff) {
  const rows = ['', '', '', '', ''];
  for (const ch of s) {
    let g = FONT[ch] || FONT[' '];
    if (ch === ':' && blinkOff) g = [' ', ' ', ' ', ' ', ' '];
    for (let i = 0; i < 5; i++) rows[i] += [...g[i]].map(c => c + c).join('') + '  ';
  }
  const r = rows.map(x => x.slice(0, -2)), w = Math.max(...r.map(x => x.length));
  return r.map(x => x.padEnd(w)).join('\n');
}
// FONT = the "Digit font" JSON above ({"0": ["███","█ █",...], ":": [" ","█"," ","█"," "], ...})

Known deviations (be aware, do not copy)
  • The web view's navigation buttons are filled (--btn background, 8px radius): the terminal rule "no filled buttons" is for the terminal panels.
  • reverse is used to show the active or selected row in the settings, alarm, timer and stopwatch lists and for running states (14 places in clock.sh). New panels should mark the selection with ›.
  • The maps tab paints the path of MapSCII bold cyan on wide terminals (one place in tmaps.py): the only colour in the clock's own panels.
  • Colour appears in installer and setup output (clock setup, install.sh warnings) and in tools/off-grid by default: those are command-line tools, not panels (offgrid-maps.py --mono follows this sheet).


Checklist before a UI change is done
  • Only white, bold and dim; no colour, no reverse on buttons.
  • Shortcuts read Label (key) and every action has a key.
  • Same pattern as the neighbouring tab: table rows, one dim hint line, › selection.
  • No line longer than the frame; clipped with …; limit is a setting.
  • Every mode keeps the same frame height (body_lines - 2).
  • Rendered at widths 70 and 100.
  • Text boxes: all keys are text, esc leaves, q still quits.
  • State is stated as it is now (Currently: …).




Resume one page · web and A4 print

The Terminal rules applied to a page people read on screen and print. Reference implementation in this repo: index.html + resume.css + resume.js (data in _data/*.json). The PDF is the browser's print of the same page: one layout, not two.


Rules
    

  • Monochrome. Text, bold, dim. The language/technology tags are dim monospace, not a colour. No icons, photo, skill bars, ratings or progress rings.
    • 

  • One page. A4 (Letter for US applications: change only @page size). Order: name and contacts, Education, Experience, Projects, Skills; newest first.
    • 

  • Section = h2 with a single bottom rule. Entry = bold name and dim role on the left, dim place and dates right-aligned.
    • 

  • Language/technology tags are optional: options.show_languages and options.languages_as_list in _data/personal.json (or RESUME_LANGS=0|1, RESUME_LANGS_LIST=0|1 per build). As a list they sit on one dim Tech: a · b line under the text instead of after the title. Strict line limit: options.max_line_chars (default 90, or RESUME_MAX_CHARS): skills, Tech lines and languages wrap to a new line between items, never mid-item; web uses --limit in ch.
    • 

  • Detail lines belong to the entry above and are marked ↳; a bold title, then the dim tags after ·, then one plain paragraph. Three lines of text per detail at most.
    • 

  • Skills are the About pattern: dim right-aligned label, plain value, facts separated by ·.
    • 

  • Links are plain text in the text colour with a 1px border underline; contacts sit on one line separated by ·. Write the visible address, not a word like "email me".
    • 

  • Web only: theme auto (follows the visitor's system, live), dark, light, e-ink; entries fold (↓ open, › closed); one dim hint line with the keys. Print: forced black on white, everything open, hint and theme line hidden, no entry split across pages, a heading never ends a page.
    • 

  • No second colour for emphasis, no two-column layout, no text under 9pt in print.
    •

Rules
    

  • Order. Name and contacts, Profile (three lines at most), Education, Experience, Publications, Talks, Teaching, Projects, Awards, Skills, Languages, References (on request). Drop a section rather than pad it; newest first inside every section.
    • 

  • Timeline = the About pattern. A dim right-aligned year column, then the entry as plain text; a range is written 2019 - 2022, an open one 2022 - Present. Detail lines are marked ↳ as in the resume, four lines of text at most.
    • 

  • Publications are numbered [n] in dim from [1] at the top, newest first (ol.pubs in resume.css); the abstract is a fold (details.abs). Your own name is bold; the venue, year and DOI are one dim line.
    • 

  • Pages. A4, margin 16mm 14mm. A running header Name · Curriculum Vitae top left and n/N bottom right, both dim and 8pt, from page 1 on. An entry is never split and a heading never ends a page.
    • 

  • Folds on the web. Each section is a fold, all open by default; on a very long CV fold the sections older than ten years. Print and PDF open everything.
    • 

  • No photo, no personal-data block beyond what an application needs, no coloured section bands, no two columns.
    •

Rules
    

  • One idea per slide, at most six lines, about 40 characters a line. If it needs more, it is two slides or a handout.
    • 

  • Hierarchy is bold and dim only. Title bold, body plain, source and notes dim. No colour, gradient, shadow, animation or transition.
    • 

  • Frame. The title slide may use the rounded dim frame of the logo; every other slide is bare text. No clip art, no photos in colour: a figure is monochrome and carries a dim one-line source.
    • 

  • Lists show every point. Progressive reveal: → steps through the points before the next slide, the current one bold with ›, the others dim; nothing is hidden. Two levels at most, the second marked ↳.
    • 

  • One number, big. A key figure is drawn with the 3 × 5 block digit font (tcBigText, see Digit font) with a dim unit line under it.
    • 

  • Footer. One dim line:  ◀ back   next ▶ left, n/N right. Keys: ← → / space / backspace, f fullscreen, n notes, t theme, p print.
    • 

  • Theme. Dark for a dark room, light for a bright one; auto follows the laptop but pick one explicitly before projecting. Print is black on white.
    • 

  • Notes fold. Speaker notes are hidden until n and never printed; the PDF handout is slides only, one per landscape page.
    • 

  • No text under 24px at 1280 wide, no more than two levels, no auto-advance.
    •

Kit: JavaScript 
// tcDeck(root): root = .sl-deck holding .sl sections. Keys while it has focus:
//   → space  next point, then next slide      ← backspace  back      f  fullscreen      n  speaker notes
// Lists reveal one point at a time: the current <li> is bold with ›, the others stay dim.
function tcDeck(root) {
  const s = [...root.querySelectorAll(".sl")];
  let i = 0,
    k = 0;
  const pts = () => [...s[i].querySelectorAll("li")];
  const mark = () => pts().forEach((x, j) => x.classList.toggle("now", j === k));
  s.forEach((x, n) => {
    const no = x.querySelector(".no");
    if (no) no.textContent = n + 1 + "/" + s.length;
  });
  const go = (n, end) => {
    i = Math.max(0, Math.min(s.length - 1, n));
    s.forEach((x, j) => x.classList.toggle("on", j === i));
    k = end ? Math.max(0, pts().length - 1) : 0;
    mark();
  };
  const next = () => (k < pts().length - 1 ? (k++, mark()) : go(i + 1));
  const back = () => (k > 0 ? (k--, mark()) : go(i - 1, true));
  root.tabIndex = 0;
  root.addEventListener("keydown", (e) => {
    if (e.key === "ArrowRight" || e.key === " ") next();
    else if (e.key === "ArrowLeft" || e.key === "Backspace") back();
    else if (e.key === "f")
      document.fullscreenElement ? document.exitFullscreen() : root.requestFullscreen();
    else if (e.key === "n") root.classList.toggle("notes");
    else return;
    e.preventDefault();
  });
  go(0);
  return { next, back };
}
